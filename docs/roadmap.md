# 收敛路线：0.11 → 0.13 → 1.0

每个 minor 只有一个主题，主题必须回答「哪类用户受益、以前怎么做、现在怎么做、如何证明变好了」。
版本纪律与 1.0 判定标准在 [versioning.md](./versioning.md)；本文只排顺序和门槛。**不承诺日历日期**——顺序即承诺。

## 已完成（2026-10 收敛批次）

- 稳定性分层 Core/Beta 落地（tiers.json + 构建盖章 + 站点徽标 + tier-direction 守卫）
- 公共契约快照六面 + tag 间 diff（`contracts:diff --gate core` = 1.0 判定第一条的机器化）
- 行为 conformance 套件（Core 26 组件）；url-safety 对抗语料；全组件精修（XSS / P0 / 逻辑缺陷）
- 封装兼容矩阵 CI（React 18/19 × Vue 3.3/3.5 四条线实跑）
- 弃用守卫 / 体积预算 / 覆盖率棘轮 / 契约-CHANGELOG 联动 / publint+attw 包面检查
- 发布链闭环：发版前全门 + tag 版本校验 + 自动 GitHub Release
- 陌生人 dogfood 首轮（8 卡点全处置，[dogfood.md](./dogfood.md)）；文档站全站中英双语

## 批次

### 0.11 —— 核心接入体验（Core）

**主题**：一个新开发者从 `bun add` 到可运行表单 + 表格页的时间压到 30 分钟内。

- 5 条核心旅程的端到端核对（新项目接入 / 后台系统 / 主题定制 / 框架封装 / RTL+暗色），每条旅程产出「常见错误与排查」段落进文档站（[faq.md](./faq.md) 是种子）；
- 首个外部试点项目接入（见下「1.0 外部门槛」——0.11 的真正验收人）；
- Core 面契约快照开始计龄（首个 diff 基线 tag = v0.11.0）。

**不做**：新组件；Beta 族新能力（图表 / AI / KB 本批次冻结面，只修缺陷）。

### 0.12 —— 升级与兼容演练（Core）

**主题**：证明「跟随 minor 升级」是可预测的。

- 至少 2 个试点项目完成一次 0.11 → 0.12 升级并记录全程（哪里卡住、文档缺什么）；
- 外部 issue 从报告到修复的公开时间线跑通第一轮；
- AI/KB 验收矩阵（[acceptance.md](./acceptance.md)）的真实读屏与触屏通过记录补齐；
- 弱覆盖模块补齐（清单在 [testing.md](./testing.md)），覆盖率地板随之上调。

**不做**：任何会动 Core 契约面的重构（除非清偿技术债且逐条公告）。

### 0.13 —— 1.0 候选（Core 冻结候选）

**主题**：Core 面两个 minor 零移除的最后一程。

- 对照 versioning.md 判定三条逐项打勾（`contracts:diff --gate core` / 全门绿史 / 文档同步）；
- 清理或显式降级残留 experimental 面；
- 真实读屏（NVDA / VoiceOver）、键盘、移动端、RTL、暗色、低性能设备的关键旅程记录；
- 发布 `1.0.0-rc.1`，收集至少两周反馈 → 无阻断则 `1.0.0`。

**1.0 同日生效**：迁移页体系（`/vm/x-to-y`，由 `contracts:diff` 生成骨架）——按既定决策，0.x 全程不预支这个成本。

## 1.0 外部门槛（自我验收之外）

| 目标 | 标准 | 性质 |
| --- | --- | --- |
| 真实接入 | ≥ 3 个非作者控制的项目使用同一 minor 线 | 运营（owner） |
| 升级验证 | ≥ 2 个项目完成一次 minor 升级且无需未公告修改 | 运营 + 工程 |
| 问题闭环 | 外部 issue 有公开处理时间线 | 运营 |
| 文档验证 | 新开发者仅凭文档完成接入，不问作者 | 工程（文档） |
| AI 接入验证 | ≥ 2 个不同 Agent 仅凭文档/llms.txt 完成组件使用任务 | 工程（可验证） |
| 无障碍验证 | 关键旅程通过真实读屏与键盘测试（不止 axe 基线） | 工程 |

**当前状态：0/6。** 这是 1.0 真正的瓶颈——不是工程，是第一批外部使用者。
