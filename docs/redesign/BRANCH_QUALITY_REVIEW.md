# pref/design 分支质量复核

日期：2026-10-21。被审提交：`1f0e296`，对比本地 `main`。本次为审计，没有修改产品源码或刷新视觉基线。

后续修正与验收结果见 [交付报告](FINAL_REPORT.md)。下文保留审计时的事实和判断。

## 判断

这是一次有实际产出的系统级视觉改造，工程基础较扎实，但还不符合“视觉、交互、逻辑、消费方集成最终统一”的完成标准。主观整体评价约 **7/10**；原报告普遍 8.5–9 分的评价偏乐观。建议继续在当前分支收口后再按终局版本验收。

肯定项：125 个文件发生变化；统一控件几何、状态填充和表面语义已有实现；六套配色事实源没有修改，四原语结构保留；没有引入运行时依赖；公共契约快照已更新且复核无漂移。官方组件文档确实形成了更统一的工具栏、侧栏、预览区与 Inspector。基础控件的改造具有可见效果。

## 应先解决的问题

### 1. 新应用组合页存在大量未接线控件

位置：`site/src/pages/apps.astro:65`、`:76`、`:102`、`:206`、`:221`、`:244`。

该页面没有页面行为脚本。站头会全局初始化 select，但这里的 select 没有任何选项数据，渲染后变为“选择选项”。开关、分段、完成/恢复、文件操作、AI 工具展开和发送也没有相应的业务接线。

真实 Chromium 复核：点击“降低透明度”前后 `aria-checked` 都为 `false`；点击数据页 `24h` 后选中项仍为 `7d`。这直接违背 AGENTS.md 的 demo 全真接线要求，也使最终报告的“四个真实应用组合”表述失准。应让所有呈现为可操作的控件具有真实本地效果，并覆盖客户端换页与销毁流程。

### 2. AI 示例教错了权限边界

位置：`site/src/pages/apps.astro:202`。

示例建议受限侧保留“存在但不可见”的入口，还要求区分“不知道”和“不能说”。这与仓库要求“对受限侧沉默”“不知道与不能说不可区分”冲突。同页 `:167` 的检索说明却采用正确口径，内部也不一致。

这是示例内容与安全契约冲突；本次没有发现由该静态文案直接造成的实际数据泄露。仍应优先修正文案，避免消费方照着实现错误边界。

### 3. 多个动效声明在变量展开后无效

位置：`src/base.css:97`、`src/components/chart-line.css:47`、`chart-area.css:44`、`chart-bar.css:49`、`chart-stack.css:23`、`chart-pie.css:28`、`chart-radar.css:52`、`popover.css:35`、`command-palette.css:74` 等。

`--icen-tx-fast/slow` 已是“时长 + 缓动曲线”，调用处又追加 `--icen-ease-*`，生成两个 timing-function。浏览器丢弃整条声明。发布 CSS 的实测结果：折线点、柱体的 transition 回退到初始值（计算序列化为 `all`，时长为零），Popover 的 animation 为 `none`。

这一模式部分已有历史存在，本分支又在图表族中新增，并继续用于新浮层动效。应统一使用复合 transition token，或明确拆成 duration 与 ease，检查浏览器计算结果，而不只检查 CSS 文本或静态截图。

### 4. 环图的固定分隔缝会吞掉真实小数值

位置：`src/behaviors/charts.ts:645`。

本分支新增每段固定扣除 2.5 单位弧长。半径 42、周长约 263.89，因此约小于 0.947% 的正数分段会归零。用 `0.5 / 99.5` 两段调用当前构建产物，第一段得到 `stroke-dasharray="0 263.89378290154264"`，正数分段实际不可见，也失去可指向的弧面。

视觉分隔应保持小数值的表达与命中能力；应按弧长约束间隙，或设计明确的小值呈现策略，并加入数据边界测试。

### 5. “降低透明度”没有覆盖遮罩

位置：`src/components/material.css:150`、`:211`、`:216`。

新规则为 modal/command-palette 遮罩增加 `blur(8px)`，但显式 reduced 属性和系统 reduced-transparency 的降级选择器都没有包含这两个遮罩。构建产物实测：`html[data-icen-transparency="reduced"] .icen-modal-backdrop` 仍得到 `blur(8px) saturate(0.9)`。

应把遮罩纳入一致的降级策略。现有材质测试只检查 `[data-icen-material="floating"]`，不能证明全部透明表面都正确降级。

### 6. Token 统一尚未完成，验收证据也不足以支持终局结论

例如 `src/components/kb-search.css:23`、`:157`、`:160` 仍直接固定 28px 控件和 13px 字号，compact 只覆盖部分行和间距；它们不能像基础按钮一样完整随统一作者旋钮、密度与触摸尺度变化。图表的部分绘图尺寸可以独立，但业务控件不应普遍靠局部固定值维持一致。

已提交视觉基线只覆盖 8 个页面及首页/按钮的明暗和 RTL 变体。全组件展开态 axe/溢出审计是有价值的广覆盖，但不等于全状态视觉或交互验收。额外主题、原语、无障碍矩阵的脚本与大部分截图在被忽略的 `.ui-audit/` 中，新的 checkout 无法仅靠版本库完整复现这些证据。当前 Playwright 配置只有 Chromium；本轮也不能据此声称 Safari/Firefox 已验收。

应提交可复现的矩阵生成与计算样式检查，并将进度拆分为“源码已改、交互通过、视觉通过、集成通过”；不能把每个 CSS 文件有 diff 直接等价于每个组件满足完成定义。
