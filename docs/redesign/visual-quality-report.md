### 人工浏览器复核

| 场景 | 观察 | 后续判定 |
| --- | --- | --- |
| 按钮文档页 | 控件整洁但仍是通用 Web 预览；sm/lg、加载、错误和平铺排列没有说明各自任务 | 先统一几何和状态，再以保存、创建、异步失败重试等场景验证 |
| AI 输入台 | 大面积空编辑面与稀疏工具条分离；模型、附件、上下文和用量的关系不明显 | 保持稳定操作轨，补全真实模型传输、上下文、附件、流式与失败路径 |
| KB 检索页 | 工具参数、查询 JSON 和结果同时争抢注意力；大量 chip 与细线让层级变弱 | 以问题→筛选→证据→原文的任务顺序重构，弱化调试信息默认权重 |
| KB 工作台 | 来源与权限并排合理，但“受限来源打码展示”文案与实际安全边界不合格 | 受限原文不得进入 DOM；权限、证据和检索必须共享同一请求与撤销状态 |
| 首页 | 氛围优先，首屏没有可操作产品任务；计数动画出现无意义中间值 | 用一个真实工作流替代装饰性首屏和计数带 |
| 应用组合 | 四个纵向窗口更像展示板，不像持续工作的应用 | 改为任务切换与共享状态的完整工作区，保留四种场景 |

### 源码确认的视觉根因

1. 焦点、禁用和反馈有三处竞争权威，不能通过局部新增 override 根治。
2. Select trailing slot 被后置尺寸规则覆盖；toggle 适配类名错误；checkbox 的选中语言不一致。
3. Option row 把键盘当前项与持久选中混成同一填色；菜单又隐藏 check，语义不一致。
4. Menu 与 popover 共享几乎相同的 scale 入场；toolbar、data row、AI/KB action 存在多个独立尺寸体系。
5. AI/KB 的固定 grid track、异步整树重建和状态几何变化会导致内部溢出与抖动；页面级 overflow 检查无法发现全部问题。
