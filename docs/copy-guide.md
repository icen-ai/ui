# 官网与 README 文案规范（copy guide）

文案纪律与代码纪律同级：本文件是审计结果、写作规范与「改前 / 改后」对照；数量类主张由 `meta.json` 构建期注入（见 `docs/contracts/README.md` 的 meta 一节），语气由本规范约束、评审把关。

## 1. 写作规范

1. **陈述事实**：只写可验证的句子。每个主张后跟证据——数字（meta.json 注入）、链接、代码示例或「运行这条命令自己看」。
2. **短句**：一句一个意思。破折号连接从句，不用排比。
3. **少形容词**：不用「强大」「优雅」「无缝」「下一代」。删掉形容词后句子仍成立，才允许保留。
4. **不写时间承诺**：「为下一个十年而生」不可验证；写「破坏性变更只进 minor，CI 强制公告」。
5. **诚实标注未知**：规范无法表示的（如 DTCG 装不下 clamp()）写明跳过，不粉饰。
6. **品牌克制**：「冰点 / ICEN」只作名字出现，不做形容词化使用；视觉层（雪花图形、印章）承担辨识度，文案不喊口号。

参考语气（学其纪律，不抄文字）：Linear 的 changelog 用短句列事实；Radix 文档以「它做什么、不做什么」开头；Vercel Geist 的规格页用表格而非形容词。

## 3. 保留项（审计后决定不改）

- 「简洁留给用户，复杂留给代码」——设计哲学陈述，primitives 页有完整论证支撑，不是形容词。
- 「点一张色卡，整站即刻换装」「下面都是实时渲染」——可当场验证的操作说明。
- hero 区的雪花图形与「冰」印章——视觉品牌层，不动。

## 4. 双语纪律

站点中文为源、英文词典逐键对应（`site-i18n.ts` 手写覆盖 + `site-i18n-en.ts` 全量兜底）。改中文必同步英文键值；含数量的键一律用 `` `${META.*} …` `` 计算键，守卫扫描裸数字。新增页面文案先在词典登记再评审。
